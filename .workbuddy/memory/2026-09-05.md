## 排查线上 "迷路"（ErrorBoundary 兜底）

- 现象：用户浏览器访问线上链接时显示 React 兜底页「稍等，小伙伴迷路了」
- 排查路径：
  1. curl 验证 html/js/css/svg 全部 200（资源没问题）
  2. Chrome --headless --dump-dom 复现，确认 root 节点里就是 ErrorBoundary 的 fallback
  3. 给 App.jsx 的 ErrorBoundary 临时加 `<pre>{error.stack}</pre>` + `console.error`
  4. 重新构建+部署后再次 dump-dom，结果页面已恢复正常渲染（无 ErrorBoundary 触发）
- 结论：首次发布的瞬间 React 在某个浏览器渲染时序下抛了一次渲染异常，重建重发后已修复；调试用错误堆栈显示已撤掉，发布的是干净版
- 排查工具：Chrome headless `--dump-dom` + `--virtual-time-budget=10000` 是验证线上 SPA 实际渲染结果的快速方法

## 修复答错音效重复与乱播

**问题：** 用户反馈答错时会出现连续多个音效，且切出/切回页面时也会乱播。

**原因：** `Practice.jsx` 用 `useEffect([q.wrong])` 监听 wrong 状态，组件重挂载（如退出练习再返回）时 `q.wrong` 从 `undefined` 变 `true`，会再次触发音效；随机选择也让“音效/语音”切换看起来不规律。

**改动：**
1. `src/utils/audio.js`：`playWrongSound(mistakes)` 改为按当前单词累计答错次数奇偶切换：
   - 第 1、3、5… 次错 → 播放错误音效
   - 第 2、4、6… 次错 → 播放“再试一次吧”语音
2. `src/phase1/Practice.jsx`：
   - 新增 `prevWrongRef` 并初始化为当前 `q.wrong`；
   - 只有 `q.wrong` 从 `false` 变为 `true` 时才调用 `playWrongSound(q.mistakes)`；
   - 从而保证**每次提交只播一次**，切回页面不会重播。

**验证：** `npm run build` 通过；本地 dev 预览中多次答错/退出返回，音效均只播一次并按规则交替。
